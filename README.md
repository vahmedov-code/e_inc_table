# AviorSign

Локальная вывеска для **Good Display ESP32-M075 V3.0**, ESP32-D0WD, Flash 4 МБ и четырёхцветной матрицы семейства **F53 / GDEM075F53, JD79665CA, 800×480**. Проект открывается в VS Code с PlatformIO.

Если устройство циклически перезапускается или не даёт подключиться к точке доступа, используйте отдельную [диагностическую сборку recovery](docs/RECOVERY.md). Она не запускает дисплей, SPI или файловую систему и выводит причину сброса каждые 5 секунд. Причина аппаратного сбоя пока не установлена.

> Профиль F53 выбран по фотографии маркировки панели пользователя. Это не F52. Поддержка протокола сверена с официальным ESP32-примером F53 от 09.07.2026. Проверки на физическом устройстве ещё не было. До прошивки проверьте маркировку панели, питание и соответствие GPIO вашей V3.0. После прошивки дисплей остаётся выключенным до отдельного подтверждения в панели.

## Возможности

- Русская адаптивная панель без CDN, облака и внешних шрифтов: `http://192.168.4.1` в точке доступа, `http://avior.local` в домашней сети (если доступен mDNS).
- Поиск доступных Wi-Fi 2,4 ГГц и выбор имени сети из списка; для скрытых сетей остаётся ручной ввод.
- Индикация подключения по фактической связи с роутером и IP-интерфейсу ESP-IDF; исходный статус Arduino выводится отдельно для диагностики.
- «Открыто», «Закрыто», «Скоро буду» и своё изображение. Встроенные русские макеты работают без файловой системы.
- PNG/JPEG преобразуются браузером в 800×480 и четыре цвета; на ESP32 отправляется кадр 96 000 байт. Макеты каждого статуса можно заменить.
- До 32 недельных событий, произвольный порядок, переход через полночь и выходные. Последнее событие сохраняет действие до следующего. Ручной статус отключает расписание.
- NTP или установка времени с телефона; фиксированное смещение UTC, по умолчанию Москва UTC+3. Автоперехода на летнее время нет. После потери питания без сети время нужно синхронизировать снова.
- Версионированный HTTP API с отдельным случайным Bearer-ключом. Контракт для будущего адаптера Avior CRM описан в [docs/API.md](docs/API.md); реальное подключение к CRM пока не реализовано.
- Отдельная задача обновляет дисплей, пока HTTP остаётся доступен. Полное обновление, ограничение частоты до одного обновления в минуту, таймаут BUSY, выключение питания и deep sleep панели после обновления.
- Настройки сохраняются в NVS `avior-sign`, изображения — в LittleFS. Автоформатирования нет. OTA-перепрошивки и команды полного стирания Flash в приложении нет.

## Проверенная документация и распиновка

Официальные источники проверены 21.10.2026:

1. [ESP32-M075, страница производителя](https://www.good-display.com/product/764.html).
2. [Страница схемы ESP32-M075](https://www.good-display.com/companyfile/2075.html), файл `ESP32-M075-SCH-20250704.pdf`, опубликован 15.06.2026. [Прямой PDF](https://v4.cecdn.yun300.cn/100001_1909185148/ESP32-M075-SCH-20250704.pdf).
3. [GDEM075F53: характеристики, JD79665CA и загрузки](https://www.good-display.com/product/546.html).
4. [Официальный ESP32-пример F53](https://www.good-display.com/companyfile/2093.html), архив `A32-GDEM075F53.rar`, версия `A32-GDEM075F53-F-20260709`.
5. [GxEPD2 F52](https://github.com/ZinggJM/GxEPD2/blob/1.6.7/src/epd4c/GxEPD2_750c_GDEM075F52.h): другой контроллер JD79665AA. Этот драйвер в проекте **не используется**.

| Сигнал | GPIO ESP32 | Контакт FPC P3 | Проверка по схеме |
|---|---:|---:|---|
| SCK | 18 | 13 | SPI_SCK |
| MOSI | 23 | 14 | SPI_MOSI |
| CS | 27 | 12 | CS |
| D/C | 14 | 11 | D/C |
| RESET | 12 | 10 | RES |
| BUSY | 13 | 9 | BUSY, низкий = занят |

MISO дисплею не нужен. Отдельного GPIO включения питания дисплея на опубликованной схеме нет. SPI MODE0, 4 МГц; только полное обновление. Код цветов контроллера: `00` чёрный, `01` белый, `10` жёлтый, `11` красный; четыре пикселя в байте, старший первым. Команды и порядок инициализации сверены с официальным F53-примером, быстрый режим не используется.

**Предел проверки V3.0:** поле Revision опубликованной схемы пустое, поэтому она не доказывает, что каждый экземпляр с надписью V3.0 имеет те же соединения. Перед первым включением проверьте соответствие FPC-сигналов GPIO на обесточенной плате либо получите подтверждение Good Display. Не подставляйте распиновку Waveshare. GPIO12 — загрузочный strapping pin, не добавляйте к нему подтяжку вверх. Не подключайте и не отключайте FPC под питанием. Подавайте питание через штатный USB платы; логика панели — 3,3 В.

## Открыть и собрать в VS Code

1. Установите VS Code и расширение **PlatformIO IDE** из официального Marketplace.
2. Выполните **Git: Clone** и вставьте:

   ```text
   https://github.com/vahmedov-code/e_inc_table.git
   ```

3. Откройте клонированную папку, где находится `platformio.ini`. Дождитесь установки закреплённых зависимостей.
4. Нажмите **PlatformIO: Build**. Не выбирайте Upload или Erase Flash на этом этапе.

Через терминал с Python 3.12:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install platformio==6.1.18
python -m platformio run
python tools/check_project.py
```

Для проверки JavaScript нужен Node.js 20+. Проект компилируется в `.pio/build/esp32-m075-v3/`. Расписание проверяют compile-time тесты в `src/schedule_checks.cpp`. Сборка не обращается к COM-портам. Интерфейс сжимается и встраивается в прошивку; **Upload Filesystem не требуется**.

Если Windows сообщает об ошибке пути при сборке внутри OneDrive или папки с кириллицей, клонируйте репозиторий в короткий локальный путь, например `C:\AviorSign\source`. Сам бэкап оставьте вне репозитория.

## Безопасная первая прошивка — только владельцем локально

Файл `C:\AviorSign\gooddisplay_factory_backup.bin` должен оставаться только на ПК владельца. Не копируйте его в проект, Issues, Releases, Git LFS или GitHub Actions. `.gitignore` исключает бинарные файлы и имена backup/factory, но не защищает от принудительного `git add -f`.

1. Убедитесь, что исходный бэкап имеет размер **4 194 304 байта**, сохраните вторую копию вне репозитория и запишите SHA256:

   ```powershell
   Get-FileHash -Algorithm SHA256 C:\AviorSign\gooddisplay_factory_backup.bin
   ```

2. Закройте Serial Monitor и заводскую программу. Определите COM-порт именно этой платы, проверьте ESP32-D0WD и размер Flash **4 МБ**. При желании используйте read-only команды esptool 4.8.1:

   ```powershell
   python -m pip install esptool==4.8.1
   python -m esptool --chip esp32 --port COM5 chip_id
   python -m esptool --chip esp32 --port COM5 flash_id
   ```

   Замените COM5 на свой порт. При включённых Secure Boot или Flash Encryption остановитесь: этот проект не предназначен для замены защищённой прошивки. Не меняйте eFuse и не обходите защиту.

3. Проверьте F53, GPIO по таблице выше и стабильное USB-питание. Подготовленный файл разделов сохраняет заводские смещения:

   | Раздел | Смещение | Размер |
   |---|---:|---:|
   | nvs | 0x9000 | 0x5000 |
   | otadata | 0xE000 | 0x2000 |
   | app0 | 0x10000 | 0x140000 |
   | app1 | 0x150000 | 0x140000 |
   | файловый раздел | 0x290000 | 0x170000 |

4. После успешной сборки выполните проверку бэкапа, указав записанный хэш вместо `ВАШ_SHA256`:

   ```powershell
   python tools/safe_flash.py --backup C:\AviorSign\gooddisplay_factory_backup.bin --sha256 ВАШ_SHA256
   ```

   По умолчанию скрипт не открывает устройство и ничего не прошивает. Он проверяет размер и хэш файла, наличие сборки и размер приложения; он не проверяет аппаратную совместимость, Secure Boot или шифрование.

5. Только когда вы готовы заменить заводскую прошивку, локально запустите:

   ```powershell
   python tools/safe_flash.py --backup C:\AviorSign\gooddisplay_factory_backup.bin --sha256 ВАШ_SHA256 --port COM5 --write
   ```

   Скрипт запросит ввод `FLASH AVIOR F53`. Обычная загрузка PlatformIO заменяет bootloader (0x1000), таблицу разделов (0x8000), OTA selection (0xE000) и app0 (0x10000). Это запись с необходимым секторным стиранием этих областей, **не полное стирание Flash**. app1 и файловый раздел не записываются; NVS не стирается этой командой, но новая прошивка добавляет свои настройки и Wi-Fi стек может сохранять параметры. Ничего не отключайте до завершения загрузки.

Здесь нет команды erase_flash. Мы не выполняем удалённую прошивку, форматирование или восстановление. Если загрузчик не подключается, используйте штатные BOOT/RESET согласно документации именно вашей платы; не замыкайте незнакомые контакты. Сохраняйте заводской бэкап для локального восстановления официальными средствами; не экспериментируйте с частичным восстановлением отдельных разделов.

## Первый запуск

1. Откройте Serial Monitor на **115200**. При необходимости кратко нажмите штатный RESET. Найдите пароль точки доступа и API token. Они генерируются случайно на устройстве и не входят в исходники. Не публикуйте снимки Serial Monitor с ключом.
2. Подключитесь к `AviorSign-…` и откройте `http://192.168.4.1`. Введите API token. Панель и API требуют этот ключ; он хранится в sessionStorage вкладки. Открытая страница интерфейса сама по себе доступ к API не даёт.
3. В «Первый запуск» проверьте профиль и отметьте подтверждение платы/матрицы. Только кнопка «Включить дисплей» разрешает работу GPIO и первое обновление (начальный статус «Закрыто»).
4. В разделе Wi-Fi можно подключить вывеску к сети 2,4 ГГц. Случайно защищённая точка доступа остаётся включённой. `avior.local` зависит от поддержки mDNS в сети; IP также показан в панели.
5. Для своих макетов нужна LittleFS. Заводской файловый раздел может быть SPIFFS: тогда монтирование не удастся, но встроенные статусы и панель продолжат работать. Только после сохранения бэкапа отдельно подтвердите «Подготовить хранилище изображений». Это форматирует **только** раздел 0x290000–0x3FFFFF, удаляя заводские файлы. Уже смонтированное хранилище эта кнопка повторно не форматирует.
6. Выберите статус: крупно показывается то, что будет на экране. В блоке «Картинка для…» загрузите PNG/JPEG или соберите текстовый макет, нажмите «Сохранить картинку»; «Вернуть стандартную» удаляет свою картинку. Сохранённая картинка текущего статуса выводится сама, для другого статуса нажмите «Показать на вывеске». PNG/JPEG обрабатывается на телефоне/ПК, ESP32 его не декодирует. На время обновления экрана (около 25 с) Wi‑Fi выключается: панель ненадолго теряет связь и переподключается сама.
7. Для расписания добавьте события открытия/закрытия отдельно для нужных дней и нажмите «Сохранить и включить». Настройте часовой пояс и проверьте время. В AP без интернета используйте «Установить время с телефона».

Ограничение в минуту объединяет частые запросы: выводится последнее желаемое состояние. После ошибки BUSY автоматический повтор отключается до нового ручного запроса или смены статуса расписанием. При нормальной работе физический экран обновляется примерно 20–25 секунд. Поле `displayed` означает завершение протокола без таймаута; у устройства нет камеры для оптического подтверждения результата.

## Безопасность и ограничения

- HTTP без TLS предназначен только для доверенной локальной сети/защищённой точки доступа. Bearer-ключ, Wi-Fi настройки и изображения передаются без TLS. Не пробрасывайте порт в интернет; используйте VPN или HTTPS-шлюз для CRM.
- CORS не разрешён, ключи не передаются в URL, API не раскрывает пароль Wi-Fi или API token. В NVS они хранятся без прикладного шифрования; физический доступ к Flash даёт доступ к настройкам.
- Чтобы отозвать ключ, нужен локальный сервисный сброс namespace `avior-sign`/смена прошивки с миграцией. Кнопка «Забыть ключ» удаляет только браузерную сессию и не отзывает ключ устройства.
- Расписание требует постоянно работающего ESP32. Deep sleep применяется к **матрице**, не к MCU; батарейный режим с длительным сном не реализован. Время без питания не сохраняется аппаратными часами.
- До 4 кадров по 96 КБ плюс временный кадр; PNG/JPEG не сохраняются. Загружайте только доверенные изображения. Конвертация использует ближайший цвет, без дизеринга.
- Нет датчика температуры, автоматической идентификации матрицы, OTA, веб-терминала, маршрутов стирания всей Flash и готового клиента Avior CRM.
- `src/schedule_checks.cpp` проверяет границы расписания при компиляции; успешная сборка не заменяет аппаратный тест GPIO, ориентации, цветов, BUSY и питания.

## Структура

```text
include/board.h       GPIO по официальной схеме
include/panel.h       framebuffer и драйвер JD79665CA / F53
include/schedule.h    недельный планировщик
src/main.cpp         сеть, API, хранение, очередь дисплея
web/index.html       автономная русская панель
scripts/embed_web.py встраивание UI при сборке
tools/safe_flash.py  локальная проверка и явная загрузка владельцем
docs/API.md          контракт API для адаптера CRM
docs/VALIDATION.md   фактически выполненные проверки
```
